60# Name of the attachment holding the raw HTML body of an inbound email. 

61# 

62# Stored with a .txt extension on purpose. The body is attacker controlled: 

63# anyone able to email a queue can put arbitrary markup and script in it, and 

64# attachments are linked straight from the ticket page and served inline by the 

65# web server, which derives the content type from the extension. Naming this 

66# .html therefore executed the sender's JavaScript in the staff member's session 

67# as soon as they opened the attachment while triaging the ticket. 

68# 

69# The stored extension is what the web server keys off, so it governs safety. 

70# The mime_type recorded in the database is a separate field used only for 

71# display and to decide what can be rendered, so it stays text/html: that is 

72# what the bytes actually are, and it is what drives the sanitized preview in 

73# helpdesk.views.staff.attachment_preview. 

74# 

75# Deliberately not wrapped in gettext: a translated filename can change the 

76# extension (es_CO rendered this as "email_html_body.html.") and so change what
